# Retro: N1, wire the web UI to the API (PR #3)

Date: 2026-10-24. Covers the session from the goal through two CodeRabbit rounds. Feeds
[ADR-0050](../decisions/0050-strategy-loop.md) and the `strategy-loop` skill.

## What happened

| Step | Shape | Result |
|---|---|---|
| Slice work | 4 parallel subagents (docs, ledger, fixed assets, reports + overview) | Everything was wired, but 3 of the 4 slices needed a second round: fields were saved silently lost, double reconcile returned 500, asset delete returned 500 |
| Coordination | Coordinator relayed messages between agents | Two agents picked the same migration number (0064), and four chained `.route()` calls hit TS2589 |
| Verification | 1 subagent wrote and ran a Playwright click-through | Found 5 real bugs that unit tests missed: the seed login had no privileges, pickers listed sample names, the asset expense list was empty, "continue" opened the list instead of a new form, and the doc number preview was wrong |
| Gate | `/no-mistakes` | Its review fixed 2 more findings (lossy adjustment and receipt edits; salvage in the depreciation report). It overwrote the PR body |
| Review | CodeRabbit, 2 rounds | 16 findings, then 4. It rate-limited after each round |

## Findings, most severe first

1. **Silent data loss was the main defect class.** No rule or check stopped a form field the API does not store
   from being dropped. Every slice hit it. *Fix:* the done-check in the skill asks "which form fields reach no
   column?", and the e2e suite saves and reloads each form (round trip).
2. **No guardrail in the repo.** The repo has no CI workflow and no pre-commit hook; only no-mistakes and
   CodeRabbit ran the checks. *Fix:* a CI job that runs typecheck, lint, `bun test` and the e2e flow.
3. **The parallel slices shared files.** `app.ts`, `route-privileges.ts`, `db.ts` and the migration sequence are
   written by every feature. Parallel agents collided on all four. *Fix:* the loop runs in one agent by default;
   parallel slices are allowed only when their file sets are disjoint and are written down first.
4. **Rework from too little context.** Subagents did not know the "no silent loss" rule or the migration
   numbering until the coordinator relayed it. Lost context between agents is the guide's first failure mode.
5. **E2E was the best evidence and came last.** It should run before the PR, not after the docs.
6. **The PR body was overwritten.** The loop must save the body before `/no-mistakes` and append afterwards.
7. **CodeRabbit budget.** The free tier gives about 2 reviews per window. The loop must treat "rate limited" as
   a normal stop and record the head SHA that is still unreviewed.

## What worked

- Ranking work by score from `docs/strategy/README.md`, and the done-when column, made "done" checkable.
- The disposable e2e agent: a long browser session whose transcript nobody needed afterwards.
- Replying in each CodeRabbit thread with the fix SHA before resolving it.
